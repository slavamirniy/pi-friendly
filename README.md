# Просто pi

Компактный интерфейс для **pi 0.84.4**: кнопки сверху чата, кликабельные slash-команды и история по проектам. Использует родной `pi-tui`, не требует отдельного сервера.

## Установка

```sh
pi install git:github.com/slavamirniy/pi-friendly
```

Перезапустите pi или выполните `/reload`. Обновление: `pi update`. Удаление:

```sh
pi remove git:github.com/slavamirniy/pi-friendly
```

## Интерфейс

В стартовом меню только:

1. **Новый разговор** — начать с чистого листа.
2. **История разговоров** — выбрать проект, затем беседу.
3. **Продолжить разговор** — появляется, если есть текущие сообщения или текст в поле ввода.

Кнопки компактные, с коротким пояснением. В чате постоянно видна **верхняя** панель:

`Меню` · `Модель` · `/ Команды` · `Подробности` · `Отправить`

Во время ответа последняя кнопка становится **Остановить**. При вводе команды — **Выполнить**. Пустое сообщение отправить нельзя. На узких экранах остаются основные действия; остальные доступны через slash-команды.

Введите `/`: варианты из настоящего автодополнения pi можно выбирать мышью. Это включает встроенные команды, установленные расширения, навыки и шаблоны. Клик подставляет выбранную команду; кнопка **Выполнить** запускает её через штатный редактор. Можно дописать аргументы перед запуском. Стрелки, Tab и Enter также работают.

Модель выбирается кнопкой в чате. Подробности разворачивают/сворачивают вывод инструментов. Клавиша F2 остаётся дополнительным способом открыть меню.

История группируется по рабочим папкам проектов, поддерживает поиск и открывается через штатный `switchSession` pi. Новый разговор создаётся в текущем проекте. Папки проектов плагин не создаёт и не перемещает. Незавершённый текст перед сменой разговора требует подтверждения.

## Совместимость

- Прогресс `pi-router-extension` и другие виджеты остаются на своих местах. Footer сохраняет все статусы расширений, в том числе остаток квоты.
- Оборачивает существующий редактор через публичный API, делегируя ввод, историю, отправку, вставку изображений и методы редактора. Если другой плагин позднее полностью заменит редактор, он может убрать эту оболочку: порядок загрузки таких расширений важен.
- Автодополнение файлов и аргументов остаётся штатным. Только список имён slash-команд получает кликабельное отображение.
- Header/footer — одиночные слоты pi. `--friendly-keep-footer` сохраняет чужой footer и отключает собственный slash-список, чтобы не перекрывать его. Верхняя панель остаётся.
- `--friendly-no-welcome` отключает стартовое меню. После создания или переключения разговора стартовое меню повторно не открывается.
- Мышь использует SGR reporting. В поддерживающих это терминалах **Shift + выделение/колесо** позволяет использовать обычное выделение и прокрутку терминала. С клавиатуры всё доступно без мыши. Кликабельные элементы сторонних плагинов зависят от самих плагинов.
- Обычные окна/селекторы pi и других расширений не заменяются; наша панель скрывается, пока они держат фокус.
- RPC/JSON/print не меняются. Плагин не делает собственных сетевых запросов и не читает API-ключи.

Это терминальный интерфейс, не графическая оболочка: шрифт задаёт терминал, цвета — тема pi. Совместимость со всеми будущими редакторами/темами не гарантируется.

## Разработка и проверка

```sh
node --test *.test.mjs
pi -e ./index.ts
```

15 тестов: попадание мышью, изменение размера окна, поиск/прокрутка, штатное выполнение команд, сторонние slash-подсказки, асинхронные гонки, сохранение методов редактора, переключение истории, статусы роутера и восстановление mouse reporting.

Smoke-проверка с установленным pi (передайте каталог пакета `@earendil-works/pi-coding-agent`):

```sh
node smoke.mjs /path/to/node_modules/@earendil-works/pi-coding-agent
```

Проверены загрузка в pi 0.84.4 и реальные VT-события клика: меню, slash-подсказка и кнопка выполнения. Тесты не требуют обращения к платной модели.

## Дизайн

Применены рекомендации [UI UX Pro Max](https://github.com/nextlevelbuilder/ui-ux-pro-max-skill): заметное состояние выбора, понятные подписи, предсказуемая навигация, отступы и сохранение фокуса. Мобильные размеры в пикселях не переносились механически в терминал. Ранние imagegen-концепты находятся в `design/`; окончательная реализация компактнее и размещает панель сверху.
